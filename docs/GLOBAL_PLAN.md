# Глобальний план розвитку LCARS Framework

## Objective
Мета
Створити повністю динамічний інтерфейс у стилі LCARS, який адаптується до вибраної фракції та епохи, забезпечуючи унікальний дизайн для Федерації, Зоряного флоту та інших фракцій (наприклад, клінгонів, ромулан, кардасіан).
## Статус виконання (Milestones)

### Phase 1: Foundation & Atmosphere (ЗАВЕРШЕНО)
- [x] **Стабілізація завантаження**: Виправлено критичні помилки імпорту та послідовність ініціалізації (`Loading` -> `Launcher` -> `Desktop`).
- [x] **Санітарія інтерфейсу**: Видалено всі подвійні слеші `//` з заголовків та логів на вимогу користувача.
- [x] **Стандартизація дизайну**: Встановлено єдиний розмір для LCARS-цеглинок (**220x60**) та забезпечено адекватні відступи.
- [x] **Динамічна палітра**: Впроваджено `LCARSColorGenerator`, що запобігає монохромності під час тривоги (Yellow/Red Alert).
- [x] **Архітектурна чистка**: Перейменовано `CoreCoordinator` на `Coordinator` (усунення тавтології) та впроваджено фасади в `lcars/__init__.py`.

### Phase 2: Core System Expansion (В РОБОТІ)
- [x] **Nexus / Engine Development**: Розроблено центральний вузол `Nexus` та ядро `Kernel` (`Coordinator`).

## Концептуальні назви для модулів Системи
Для майбутньої розробки та іменування компонентів ядра (`lcars.core`) визначено наступні варіанти:

### Тематичні (Star Trek Style):
- **Kernel (Ядро)** — Комп'ютерна класика, ідеально для `lcars.core`.
- **Nexus (Нексус)** — Центральний вузол зв'язку всіх потоків даних.
- **Mainframe (Мейнфрейм)** — Солідна назва основного обчислювального блоку.
- **ODN (Optical Data Network)** — Автентична мережа передачі даних Федерації.
- **Matrix (Матриця)** — Структура обчислювальних систем.

### Архітектурні (Modern Tech):
- **Engine (Двигун)** — Рушійна сила всіх процесів.
- **Orchestrator (Оркестратор)** — Керування сервісами та плагінами.
- **Hub (Хаб)** — Центр розподілу подій.
- **Shell (Оболонка)** — Зовнішній шар управління.

### 5. **Оновлення документації**

Примітки:

- Локальна автоматизація навмисно не запускає GUI-код (екран не потрібен). Якщо потрібно, щоб демонстрації рендерилися автоматично, можна додати крок headless-рендерингу із використанням віртуального фреймбуфера або віддаленої машини.
- Якщо хочете, щоб я створив XML для Task Scheduler або зареєстрував заплановане завдання зараз — підтвердіть, і я додам скрипт реєстрації.

**Огляд десктопа**

- **Мета:** Надати повноекранний безрамковий десктоп у стилі LCARS, який відкриває основні робочі процеси (операції з проєктами, аналітика, термінал, файловий менеджер, меню Пуск) та стійко працює при частковому відновленні чи відсутності опціональних залежностей.
- **Основний UX-потік:** Блокування/авторизація → Mission Hub / Меню Пуск → Відкриття додатків (Operations, Analytics, Terminal, File Manager) → Системні дії (Вимкнення, Блокування, Вихід).

**Основні компоненти**

- **Mission Hub / Welcome:** центральне вітання, швидкий доступ до `Start Menu`, годинник/stardate, індикатор стану.
- **Start Menu:** список додатків, пошук, улюблене та ярлики до `Operations`, `Analytics`, `Terminal`, `File Manager`, `Settings`.
- **Operations Panel (`OperationsWidget`):** виявлення проєктів, автоматизація збірки/запуску, лог термінала, кнопки `REFRESH`, `BUILD`, `RUN`, `OPEN FOLDER`.
- **Analytics Panel (`AnalyticsWidget`):** показ живих метрик системи (CPU, пам'ять, I/O), візуальний спектр-бар, індикатори стану, таймер оновлення.
- **Terminal (`LCARSTerminalWidget`):** виконання shell-команд, читач stdout у окремому потоці, робоча директорія на рівні проєкту.
- **File Manager:** дерево файлів, відкрити у ОС, контекстні дії (копіювати, перемістити, показати) — у разі відсутності модулю можливий зовнішній або простий fallback.
- **Settings & Logs:** легкий модуль налаштувань і перегляду логів для швидкого усунення проблем.

**Принципи дизайну та взаємодії**

- **Безрамковий, повноекранний:** `LCARSDesktop` запускається без стандартної рамки вікна, елементи керування — у стилі LCARS.
- **Ера-орієнтована палітра:** використовувати палітри з `lcars.themes.lcars_palette` і за потреби анімацію кольорів кнопок.
- **Прогресивне поліпшення / graceful degradation:** компоненти опціональні; десктоп має стартувати навіть при відсутності деяких модулів або шрифтів.
- **Керування через клавіатуру:** скорочення для основних дій (Alt+S = Start Menu, Alt+O = Operations, Alt+T = Terminal).
- **Неблокуючий ввід/вивід:** довготривалі задачі (збірка/запуск, команди shell) виконуються у фонових потоках та передають вивід у UI через черги/сигнали.

**Фолбеки та стійкість**

- Якщо імпорт віджету падає (відсутній файл або залежність), показувати плейсхолдер зі стислим поясненням, кнопкою `REFRESH` і посиланням на `docs/desktop_ui_plan.md` для інструкцій з відновлення.
- Якщо відсутні шрифти/ресурси — використовувати системні шрифти; `get_lcars_font_style()` має забезпечувати консистентні розміри.
- Обгортати опціональні модулі у `try/except` на межах імпортів (вже застосовано у `lcars.modules.__init__`).

**Доступність та тестування**

- Забезпечити читабельність (контраст) палітр; додати перемикач доступності для збільшення розміру шрифтів.
- Написати юніт-тести для критичної логіки: `ProjectManager.get_all_projects()`, `TaskExecutor.execute_command()`, обробка виводу термінала.
- Візуальні smoke-тести: запуск `start.py` у headless-режимі з моками віджетів для перевірки відсутності імпортних помилок; після цього — інтерактивна перевірка потоків `Operations` (build/run).

**Примітки для розробників та мапінг файлів**

- Shell десктопа: `lcars/ui/desktop.py` — оркестрація макету та підключення віджетів.
- Віджети: `lcars/ui/widgets/operations.py`, `analytics.py`, `terminal.py` — ключові модулі (відновлені).
- Тема: `lcars/themes/lcars_palette.py` — палітри та функції `setup_lcars_font()` і `get_lcars_font_style()`.
- Старт: `start.py` — використовує `LCARSWindowManager` для показу lock/desktop.

**Наступні кроки (порядок реалізації)**

1. Замінити тимчасові шими повноцінними віджетами (Operations, Analytics, Terminal) — ключові віджети відновлено.
2. Відновити або реалізувати `FileManager` і `StartMenu` (або додати стабільні плейсхолдери).
3. Інтегрувати вихід `TaskExecutor` з опитуванням у `OperationsWidget` і протестувати build/run на прикладі проєкту.
4. Додати клавішні скорочення та налаштування доступності.
5. Провести візуальну та функціональну валідацію; виправити залишкові імпорт/рантайм-помилки.
6. Прибрати тимчасові шими та зафіксувати відновлені файли в recovery-гілці; за потреби підготувати очищену історію.
