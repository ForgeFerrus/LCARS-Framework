# Global Plan for LCARS Framework Development

## Objective
Мета
Створити повністю динамічний інтерфейс у стилі LCARS, який адаптується до вибраної фракції та епохи, забезпечуючи унікальний дизайн для Федерації, Зоряного флоту та інших фракцій (наприклад, клінгонів, ромулан).

---

## Tasks Breakdown

### 1. **Компоненти інтерфейсу, специфічні для епохи**
- **Ціль**: Спроєктувати і реалізувати унікальні компоненти інтерфейсу для кожної епохи та фракції.
- **Підзадачі**:
  - Розробити кнопки, панелі та підписи для Федерації (22‑те, 23‑є, 24‑те, 25‑те століття).
  - Створити відмінні дизайнерські рішення для клінгонів і ромулан.
  - Забезпечити модульність і повторне використання компонентів.

### 2. **Динамічна зміна теми**
- **Ціль**: Забезпечити плавну зміну тем і дизайнів залежно від вибору користувача.
- **Підзадачі**:
  - Інтегрувати логіку перемикання тем у демонстраційний скрипт.
  - Перевірити, що всі компоненти оновлюються динамічно.

### 3. **Інтеграція палітр і тем**
- **Ціль**: Забезпечити централізоване керування палітрами та коректну інтеграцію з темами.
- **Підзадачі**:
  - Завершити палітри для всіх фракцій і епох.
  - Динамічно зіставляти палітри з компонентами інтерфейсу.

### 4. **Покращення демонстрації**
- **Ціль**: Показати всі доступні теми та компоненти у демонстрації.
- **Підзадачі**:
  - Додати у демонстрацію вибір фракції та епохи.
  - Динамічно відображати відповідні дизайни.

### 5. **Оновлення документації**
- **Ціль**: Забезпечити зрозумілі інструкції для розробників і користувачів.
- **Підзадачі**:
  - Задокументувати структуру і використання тем та палітр.
  - Оновити довідник розробника з інструкціями щодо додавання нових фракцій або епох.

## Робочий процес розробки
1. **Проєктування компонентів, специфічних для епохи**:
  - Почати з Федерації (22‑те, 23‑тє, 24‑те, 25‑те століття).
  - Перейти до клінгонів і ромулан.
2. **Інтеграція компонентів з темами**:
  - Зіставити компоненти з палітрами і темами.
3. **Покращення демонстрації**:
  - Додати варіанти вибору фракцій і епох.
  - Забезпечити динамічні оновлення.
4. **Тестування і валідація**:
  - Запустити тести для всіх компонентів і тем.
5. **Документування прогресу**:
  - Оновлювати документацію після кожного великого етапу.

- Федерація і Зоряний флот повинні суворо дотримуватися тем LCARS.
- Дизайн для клінгонів і ромулан має бути відмінним і відображати їх культуру.

- Сконцентруватися на безпомилковому виконанні та плавному користувацькому досвіді.

## Автоматизація без нагляду (локально та у CI)

- У корені репозиторію додано легкий локальний запуск `nightly_run.ps1`. Скрипт виконує `scripts/auto_tasks.py` і записує об'єднаний вивід stdout/stderr у `logs/auto_work.log`.
- `scripts/auto_tasks.py` виконує безпечні перевірки без GUI, придатні для запуску без нагляду: синтаксичні перевірки (`py_compile`) та пошук тестів `unittest`. Його вивід записується в `logs/auto_tasks.log`.
- Додано CI-воркфлоу `.github/workflows/nightly.yml`, який запускається при пуші та за розкладом (щодня) і виконує `scripts/auto_tasks.py` на `ubuntu-latest`.

Як увімкнути локальні безперервні запуски:

1. Переконайтеся, що встановлено Python 3.11+ і (за бажанням) залежності проєкту:

```powershell
python -m pip install -r requirements.txt
```

2. Щоб протестувати автоматизацію локально, виконайте:

```powershell
.\nightly_run.ps1
```

3. Щоб запланувати завдання в Windows Task Scheduler, створіть задачу, яка запускає `powershell.exe` з аргументом `-File "C:\path\to\repo\nightly_run.ps1"` за потрібним розкладом. Скрипт запише `logs\auto_work.log` та `logs\auto_tasks.log`.

Примітки:

- Локальна автоматизація навмисно не запускає GUI-код (екран не потрібен). Якщо потрібно, щоб демонстрації рендерилися автоматично, можна додати крок headless-рендерингу із використанням віртуального фреймбуфера або віддаленої машини.
- Якщо хочете, щоб я створив XML для Task Scheduler або зареєстрував заплановане завдання зараз — підтвердіть, і я додам скрипт реєстрації.
